`otaman doctor` now tells you the right thing when the retired
`.agents/current-agent` marker keeps coming back. If the marker is committed
to your otaman repo, git restores it after every `otaman init --update` — the
check now says so and tells you to untrack it, instead of sending you to hunt
for a hook that was never writing it.

`otaman scan` now adds any missing runtime-exclusion lines to an existing
`.gitignore` instead of skipping the file entirely. Programs that already had
a `.gitignore` for any other reason were silently versioning their bus,
queues, sessions and agent marker; `otaman scan --update` now fixes the
exclusions and reports which runtime paths git is already tracking. It never
untracks anything for you — on some programs those commits are the only
durable copy of that state.
