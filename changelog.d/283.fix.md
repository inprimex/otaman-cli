`otaman init` now asks before it writes. It already printed the program it had resolved —
the path, the project name and the repo count — but then went ahead and wrote `.agents/`,
`launcher/`, `policy/` and a `.otaman` marker into every declared repo without waiting for
an answer. In a terminal it now prompts `Proceed? [y/N]`, and anything other than `y`/`yes`
declines and writes nothing. Scripted and non-interactive callers (no terminal attached)
must pass `--yes`; without it the command refuses and exits non-zero rather than assuming
you meant to proceed.

The prompt repeats which program you are authorising, because the validator's output sits
between the first echo and the question. `--dry-run` is not gated — it writes nothing, so
there is nothing to agree to.
