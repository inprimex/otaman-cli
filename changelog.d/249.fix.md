`otaman cleanup` no longer deletes anything unless you ask it to. Deleting whole archive
months now requires `--purge`; without it, months past the deletion window are reported
and kept. On its first successful run after a long outage, cleanup destroyed 591 messages
— archiving them and then purging the months it had just created, seconds apart.

A month that the same run archived into is never deleted in that run, even with
`--purge`. The retention window is meant to measure time spent as an archived message,
and that clock starts when the message is archived.

The report now separates moving from destroying. Archival says it is recoverable;
deletion says PERMANENTLY, counts messages rather than directories, names the months, and
states that the data is unrecoverable unless the directory is version-controlled. A dry
run speaks in the future tense and predicts exactly what the real run would do, including
which months it would refuse to delete.
