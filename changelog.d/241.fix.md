The console program picker no longer hides a tenant's programs behind a leftover
configuration file. A pre-migration `platform.yaml` left at an organisation root is
structurally valid, and because every real program sits physically beneath that
root, the picker's "ignore nested copies" rule discarded all of them and listed the
leftover alone — one program instead of five on one tenant.

Programs in the canonical layout are now never dropped in favour of a shallower
non-canonical ancestor, and the leftover is excluded with a warning naming its path,
so it gets cleaned up rather than silently shadowing programs again after someone
works around it.

Ignoring nested copies now applies only where it was meant to: a stray
`platform.yaml` inside a program's own declared repository directories. That case is
still ignored — and in fact is now ignored correctly for the first time, since the
old rule only matched copies beneath the configuration directory itself, which is
not where repositories live.
