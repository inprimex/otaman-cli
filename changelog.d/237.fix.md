Two readers now consume the shared implementations otaman-core published for them,
rather than keeping local copies.

The spec-approve action no longer composes the approval attestation string itself;
core writes it. A format with two writers is one a stricter reader can drift from,
and that drift had already turned CI red once.

The security-gate configuration is read from wherever it currently lives. The block
is moving out of `platform.yaml` into `verification-gates.yaml`, and this reader
would have reported a program with a configured ladder as having none the moment
the block moved. A `verification-gates.yaml` that exists and cannot be read now
reports as not-checked rather than as an absent configuration.
