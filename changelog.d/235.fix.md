`otaman knowledge add --domain` now tells the truth about what it checked. A
program whose vocabulary registry exists but declares no terms was told there was
no registry at all, and its term was recorded as "not validated" rather than
refused as undeclared. A registry that exists and cannot be parsed got the same
"no registry" message, so a broken file was indistinguishable from a missing one —
two situations that need opposite responses: declare the term, or fix the file.

The confirmation line also names the domain it recorded. It listed the function
and not the domain, which reads as though the flag had been ignored.

An unrecognised evidence anchor is still recorded with a warning, and the warning
now names the shapes that are recognised — a file:line, a bus message stem, or a
measured number — instead of only saying that this one is not one of them.
