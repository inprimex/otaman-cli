`otaman init --update` now reports what regenerating agent instructions actually
did: how many files were refreshed, how many were already current, and how many
failed — naming the repos. It said nothing about them before, printing only a count
of marker files and the generator's exit code, which is how 18 instruction files on
one fleet sat four months out of date across 19 generator releases while two merged
instruction fixes reached nobody.

The outcome is measured from file content before and after, so a generator that
reports success without writing anything is now a failure of the run rather than a
silent pass. Zero work is stated explicitly, because printing nothing when nothing
changed is indistinguishable from not having looked.

Where a generated file carries no generation stamp, the run says so and names how
many — the signal that would have made the four-month freeze visible on any single
run.
