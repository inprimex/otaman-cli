Registry writes (`otaman outcome`, `otaman solution`, `otaman persona`) now go
through one shared write path, so a status change always carries its audit entry
and your comments and key order survive every write. Two changes you will
notice: `outcome accept-cost`, `choose` and `reject-cost` now record who
authorized the decision and refuse (writing nothing) when no human from the
program's `human-roster` is resolved — set `OTAMAN_HUMAN`, or file an
`outcome-proposal` if no human is behind the call; and a mismatched
otaman-core refuses the write with a clear message instead of writing the file
a different way.
