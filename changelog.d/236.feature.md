`otaman policy routes` shows which model family each agent is routed to, the
active backend, and — where a route sends content outside the tenant while the
program declares content classes that must stay inside it — which agents will have
guarded calls refused when they dispatch. `otaman doctor` reports the same thing,
so a routing mistake surfaces as a configuration finding instead of a refusal
mid-call.

A program with no router configuration is unchanged, and the surface says so
rather than leaving you to infer it from an empty listing. An agent that declares
no route is listed as using the default path, because an agent missing from the
listing could equally mean nobody configured it or nothing looked at it. A routing
block that exists and cannot be read reports as not-checked and exits non-zero —
never as "no routing configured", which is the opposite fact.
