`otaman blocked <slug>` now takes `--change <slug>`, and uses it as the entry's
stable reference. Without one the entry has nothing it can be resolved against,
so every entry this command had ever written was reported as stale by
`otaman blocked --list` and `otaman check` — the only way to register a live
block was to hand-edit the file the command exists to replace.

A `--change` that names no real change is refused with a near-miss suggestion,
using the same check `otaman complete` applies, rather than written as an entry
that reads like it points at an archived change. Registering without the flag
still works — a wait on a human decision has no change slug — and now says
plainly that the entry will read as stale.

The blocked status record also carries the change now, instead of `change: null`
beside an entry that names one.
