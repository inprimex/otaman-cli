`otaman policy critics` and `otaman doctor` now resolve `role-based` critic selection
from your configuration alone. A hook that declares `target-role:` alongside the
`roles:` table names the critic it will actually select, where previously this command
could only report that it could not know — the role was supplied by the dispatcher at
review time and was invisible to a checkout. The chain also shows the role it selects
by, so `stakeholder-affected → role-based   (by role 'reviewer')` can be read against
the roles table printed below it.

Because the answer is now computable before a proposal is dispatched, the self-owned
proposal check catches a case it previously had to stay silent on: if the only agent
holding a hook's target role is the agent making the proposal, that agent's own
proposals still select no critic, and `otaman doctor` names them. A configuration can
be complete and correct in shape and still cover nobody, depending on who holds which
role.
