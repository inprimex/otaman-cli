`otaman spec status --cut-eligibility` now answers, per change, whether a release
cut may ship it: every implementation task filed complete and the verification
gate passed, or exactly which tasks are still outstanding. A change whose gate
state cannot be determined reads `not-checked` rather than quietly counting as
ready, and a verdict that rests on one blanket `--all` filing says how many tasks
it is covering — so a half-finished change cannot reach a cut unnoticed.
