`otaman cleanup` archives again. Its timestamp parser tried a fixed list of three
formats, none of which accepted fractional seconds — while every message the bus
writes carries them. On a four-month-old fleet bus that rejected 98.4% of
messages, and each rejected one was skipped before the age and ack checks ran, so
the command reported "Nothing to clean up." over 6,980 unarchived messages. The
first run after this fix archives about 2,400 of them.

The parser now accepts anything the writer can produce, because it uses the
matching reader for the writer's format instead of a hand-maintained list.

Cleanup also reports what it could NOT examine — the count of messages with an
unparseable or absent timestamp, with examples — and no longer says "Nothing to
clean up" when it skipped part of its input. It reports how many messages are old
enough to archive but still waiting on an acknowledgement, which is the next
question anyone asks.
