Changelog fragments are now enforced at merge: a pull request that changes
shipped code is blocked unless it carries a customer-facing note in
`changelog.d/`, so release notes are written by the person who made the change
instead of being reconstructed from commit history afterwards. Docs-only and
test-only changes pass untouched, and a genuinely note-free change can say so
with `changelog: exempt` in the PR body.

After a release, `otaman release clear-fragments <manifest>` removes exactly the
fragments that release consumed — by name, never by pattern — and keeps any
fragment edited since the cut, so unreleased notes cannot be swept away.
