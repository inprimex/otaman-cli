`otaman connection check` now tells you what **changed** since the last check, not only
what the status is now. A connection that has just started failing reads
`CHANGED since last check: ok → auth-failed`; one that was already failing says
`change: none`; and a connection with no earlier check says so rather than looking stable.

The previous verdict was already being recorded on every check and then overwritten
without being read — so the one fact that makes a new failure worth acting on, that it is
new, was lost by the act of measuring. This matters most for credentials that expire: an
`auth-failed` that appeared since yesterday is a rotation to do, while one that has been
there for a month is something else entirely.
