The list of message types `otaman send` accepts now comes from otaman's own
message-validation layer instead of being maintained separately by the CLI. There is no
change to which types you can send today — the two lists agreed — but they can no longer
disagree tomorrow, which is what went wrong when `decision-required` was valid everywhere
except in the CLI's copy.

If you run a CLI newer than your otaman core, the send command now offers any type core
considers valid rather than refusing what it cannot classify. Refusing was the direction
that broke things: a type the CLI does not recognise is far more likely to be a new one it
should let you send than one it should block.
