`otaman project add <name> --owner <agent>` now creates a repo end-to-end: it
creates the remote through your configured git host when a token resolves
(local-only, with a warning, when none does), clones it beside the program,
registers it in `platform.yaml`, runs `otaman init`, and commits. If `init`
fails the registration is rolled back and the directory is left on disk for
you to inspect, so a half-added repo never lingers in `platform.yaml`.

`otaman project remove --delete-remote` is now wired to actually delete the
remote. It asks you to type the repo name to confirm, refuses outright when
there is no interactive terminal, and leaves the repo registered if the
deletion fails — a remote that still exists is never left without a record
of where it is.
