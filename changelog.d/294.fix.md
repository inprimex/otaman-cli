When `otaman scan` finds runtime paths that git is already tracking, it now
tells you both consequences instead of one. As before, the new `.gitignore`
line does not untrack what is already committed — but from that point on, new
files under those paths are ignored and never enter git at all. If you were
relying on those commits as a backup, it is now frozen at the files listed,
and it stops growing silently. The command still never untracks anything for
you.
