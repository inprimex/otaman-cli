Two actions the console displayed but could not perform are now pressable.

**Ratify** (`y`) works on the changes tree, not only on the lifecycle screen. A
complete-but-unarchived change marked `◀ you` previously named the `otaman ratify`
command because no key existed where the marker was shown; it now names the key you can
press on that screen, prompts for the mandatory reason, and writes the same record the
command does — the two share one implementation rather than two that happened to agree.

**Answer** (`w`) replies to a `decision-required` from the grouped Messages view, where
you are already reading, instead of only from the opened message — and it was previously
bound to no key at all, so it could not be reached from the keyboard. The reply now
carries an `in-reply-to` link to the question, which is what `otaman check` matches on to
tell a waiting agent its decision has been answered; without it the answer arrived
unlinked. `otaman send --in-reply-to <stem>` exposes the same link to any caller.
