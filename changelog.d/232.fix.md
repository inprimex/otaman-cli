Four console fixes from a human test drive, each of which had shipped as an
intention rather than behaviour:

- **The `→`/`←` arrow keys now expand and collapse tree rows.** The key strip
  has advertised them on every lens since the arrow ruling; nothing was ever
  bound to them, because the underlying tree widget binds `space` and
  `shift+arrow` and leaves the plain arrows alone.
- **A change now nests under its outcome.** The tree read only the free-text
  `outcome:` sentence and never the `outcome-id:` stamp that is the actual
  back-link. Measured on a live program: 72 changes, none linked, 26 of them
  carrying a perfectly good stamp. A change that names an outcome the registry
  does not have is now grouped and labelled as such instead of being buried
  among genuinely unlinked ones.
- **The "N awaiting you" count names the filter that selects it (`:a`).** The
  filter shipped and could not be found, because it appeared in no place anyone
  looks at while using the screen.
- **Leaving Messages no longer throws away what it loaded.** The in-memory store
  is now owned by the app for the whole session instead of being rebuilt on
  every visit. Re-entry at 984 pending messages: 374ms of rescanning before,
  0.24ms now.
